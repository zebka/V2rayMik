# mikrotik-xray-gateway (فارسی)

[English README](README.md)

ترافیک «جهان» روتر میکروتیک را از طریق **یک** کانتینر Alpine که
[sing-box](https://github.com/SagerNet/sing-box) را با اینترفیس TUN بومی خودش اجرا
می‌کند بیرون می‌برد. بدون tun2socks، بدون کانتینر دوم، بدون فایل geosite، و همراه
با یک پنل کوچک روی شبکهٔ محلی برای گرفتن سابسکریپشن و عوض‌کردن نود.

> نام مخزن و ایمیج تاریخی است؛ از نسخهٔ **0.5.0 موتور sing-box** است (تا 0.4.x
> Xray بود). همین است که یک دروازه می‌تواند نودهای **hysteria2**، tuic،
> vless/REALITY، vmess، trojan و shadowsocks را با هم ببرد.

میکروتیک پروتکل‌هایی مثل VLESS/REALITY یا hysteria2 را نمی‌فهمد. این پروژه همان
شکاف را پر می‌کند، بدون اینکه تفکیک ایران/جهان از روتر برداشته شود.

## چرا این شکل؟

- **TUN مال خود موتور است.** RouterOS دستگاه `/dev/net/tun` را به کانتینر می‌دهد و
  sing-box می‌تواند خودش اینترفیس را بسازد و بخواند. Tun2socks از مسیر حذف
  می‌شود: یک پروسه، یک ایمیج، یک نقطه‌ی خرابی کمتر.
- **روت‌ها دستی‌اند.** `auto_route` خاموش است: خود کانتینر دو روت `/1` و یک `/32`
  برای سرور می‌گذارد، پس همه‌چیز به longest-prefix match وابسته است، نه به ترتیب
  `ip rule` که RouterOS از ۷.۲۲ عوض کرد و TUN gatewayها را شکست.
- **بدون iptables و بدون NAT داخل کانتینر.** کانتینر کرنل RouterOS را شریک است و
  ماژول‌های netfilter آن قابل اتکا نیستند. روتر خودش ترافیک LAN به کانتینر را
  masquerade می‌کند، پس کانتینر فقط `172.17.0.1` را می‌بیند.
- **تفکیک مسیر روی روتر می‌ماند.** `iran-ips` تعیین می‌کند چه چیزی تونل شود؛
  کانتینر هیچ قاعده و هیچ فایل جغرافیایی ندارد.

## نودهای پشتیبانی‌شده

| پروتکل | نکته |
| --- | --- |
| `vless://` | با REALITY و `xtls-rprx-vision` |
| `vmess://` | |
| `trojan://` | با TLS و WebSocket/gRPC |
| `ss://` | |
| `hysteria2://` و `hy2://` | روی UDP؛ obfs از نوع salamander و `pinSHA256` هم |
| `tuic://` | |

ترنسپورت‌ها: TCP، WebSocket، gRPC و HTTPUpgrade. **xhttp/splithttp پشتیبانی
نمی‌شود** و پنل هم همین را می‌گوید، نه اینکه بی‌صدا شکست بخورد.

hysteria2 و tuic روی UDP کار می‌کنند؛ پورتشان باید در allowlist کانتینر روی روتر
باشد، وگرنه پنل `port blocked` نشان می‌دهد.

## پیش‌نیازها

- RouterOS 7.24 یا بالاتر (روی ۷.۲۵.۱ تست شده) با پکیج **container**.
- حالت کانتینر فعال، که **دسترسی فیزیکی** می‌خواهد
  (`/system/device-mode/update container=yes` و تأیید روی دستگاه).
- یک دیسک خارجی برای `root-dir` و `tmpdir`. فلش داخلی نه جا دارد نه عمر.
- DNS سالم روی روتر. اگر `:resolve twitter.com` جواب `10.10.34.x` داد، اول DNS را
  درست کن، تونل را متهم نکن.
- یک سرور (Xray یا sing-box) که از قبل داری؛ هر نودی که اپراتور به شکل لینک
  اشتراک می‌دهد قبول است.

## شروع سریع

۱. ایمیج را بگیر. مالتی‌آرک روی Docker Hub هست و روی GHCR هم:

```
docker pull azebka/mikrotik-xray-gateway:latest # آخرین نسخهٔ منتشرشده
docker pull azebka/mikrotik-xray-gateway:0.5.0 # نسخهٔ ثابت، هم‌ارز با همین مخزن
docker pull ghcr.io/zebka/mikrotik-xray-gateway:latest
```

تگ `latest` فقط با پوش‌شدن یک تگ ریلیز به‌روز می‌شود، پس همیشه با فایل `VERSION`
و آخرین نسخهٔ همین مخزن یکی است. `edge` بیلد خام `main` است و برای تست است. نسخهٔ
در حال اجرا در پنل زیر **Status → image** دیده می‌شود.

اگر به `ghcr.io` دسترسی نداری، از Docker Hub (یا میرور داخلی) استفاده کن. روی
خود روتر، در ایران این تنظیم جواب می‌دهد:

```
/container/config/set registry-url=https://docker.iranserver.com check-certificate=no
```

یا با `make image` محلی بساز، یا با `make save` فایل tar بگیر و کنار بگذاری
(`docs/install-side-load.md`).

۲. outbound را جایی بگذار که کانتینر بخواند: یا فایل کامل
`<disk>/xray-gw/etc/sing-box/outbound.json`، یا لینک اشتراک در env با کلید
`NODE_LINK` (نام قدیمی `XRAY_LINK` هم کار می‌کند). **هر دو را با هم نده.** پورت آن
لینک باید در `XrayContainerToWanPorts` باشد؛ توضیحش در `docs/security.md`. برای
hysteria2 و tuic که UDP هستند هم همین قاعده است.

۳. اسکریپت‌ها را **در یک نشست** و به ترتیب ایمپورت کن:

```
/import file-name=00-vars.rsc
/import file-name=01-container.rsc
/import file-name=02-routing.rsc
/import file-name=03-firewall.rsc
/import file-name=04-admin.rsc
/import file-name=05-auto-route.rsc
```

اول `00-vars.rsc` را ویرایش کن: اینترفیس WAN، سابنت LAN، نام دیسک و اگر پنل
می‌خواهی `XrayAdminPassword`.

`05-auto-route.rsc` اختیاری است ولی توصیه می‌شود: همان چیزی است که باعث می‌شود
روتر نودی را که در پنل انتخاب می‌کنی دنبال کند.

۴. کانتینر را استارت کن و لاگ را ببین:

```
/container/start [find where name="xray-gw"]
/log print where topics~"container"
```

۵. از یک کلاینت LAN تست کن: `curl https://ifconfig.me` باید IP سرور را بدهد.

۶. پنل (اختیاری): از یک دستگاه LAN برو به `http://<router-lan-ip>:8081/`، با
`XrayAdminPassword` وارد شو، آدرس سابسکریپشن را بده، **Test all** بزن و روی
نودی که می‌خواهی **Connect** کن.

بازگشت عقب: `99-uninstall.rsc`. اول روت را برمی‌دارد تا ترافیک بلافاصله از تونل
بیرون بیاید.

## رفتار در قطعی

`XrayFailOpen` در `00-vars.rsc`:

- `true` (پیش‌فرض): یک روت مستقیم از گیت‌وی ISP با distance 2 می‌ماند. وقتی تونل
  قطع شود، ترافیک دنیا با IP واقعی خود روتر و از همان کشور بیرون می‌رود. اینترنت
  قطع نمی‌شود، ولی IP واقعی برای مقصدها دیده می‌شود.
- `false`: هیچ fallbackی نیست. چیزی لو نمی‌رود؛ مقاصد «جهان» تا وقتی تونل قطع است
  جواب نمی‌دهند.

هر دو عمداً هست؛ انتخابش با توست. `docs/security.md` را بخوان.

fallback عمداً **هیچ‌وقت یک تونل دیگر نیست**. اگر OpenVPN یا WireGuard را جای
fallback بگذاری، مرگ نود Xray پنهان می‌ماند و کشور خروج بی‌صدا عوض می‌شود؛ همان
چیزی که برایش پول می‌دهی.

### دنبال‌کردن خودکار پنل

`router/05-auto-route.rsc` هر ۳۰ ثانیه از `cgi-bin/health` می‌پرسد
(`selected=`، `up=`، `live=`). فقط وقتی هر سه `1` باشند روت `xray-world` فعال
می‌ماند؛ وگرنه خاموش می‌شود و روت گیت‌وی ISP روشن می‌شود و بقیهٔ روت‌های پیش‌فرض
(OpenVPN، WireGuard) خاموش می‌مانند. تا وقتی این scheduler روشن است، مالک جدول
مسیریابی است: برای استفاده از یک تونل دیگر، اول scheduler را خاموش کن.

گیت‌وی ISP هر بار از جدول `main` خوانده می‌شود، پس تغییر DHCP یا PPPoE نیازی به
ویرایش ندارد.

## پنل مدیریت

همان کانتینر یک صفحهٔ کوچک روی LAN سرو می‌کند: سابسکریپشن، تست هر کانفیگ و
عوض‌کردن نود فعال.

```
http://<router-lan-ip>:8081/ # XrayAdminLanPort
```

- **سابسکریپشن:** آدرس سابسکریپشن v2ray (base64 یا لینک خام) یا یک لینک تنها.
  همه‌چیز محلی پارس می‌شود.
- **تست:** هر کانفیگ یک sing-box کوتاه‌عمر با inbound از نوع mixed می‌گیرد، بعد چک
  `generate_204` و یک دانلود ۱۰ مگابایتی. تونل اصلی در تمام مدت کار می‌کند.
  «Test all» کل لیست را می‌رود و «Cancel» وسط کار متوقفش می‌کند.
- **اتصال:** ترافیک دنیا به همان کانفیگ منتقل می‌شود. نتیجه بررسی می‌شود (TUN بالا،
  روت‌ها درست، پاسخ ۲۰۴ از داخل تونل) و اگر نود بالا نیاید خودکار برمی‌گردد. حدود
  ۲ تا ۳ ثانیه اتصال‌ها می‌افتند و چیزی لو نمی‌رود، چون روت دنیا همچنان به کانتینر
  اشاره می‌کند.

دو کاری که پنل عمداً انجام نمی‌دهد:

- کانفیگی که پورتش بیرون از allowlist است وصل نمی‌شود؛ آن ردیف‌ها «port blocked»
  نشان می‌دهند.
- خودش را به WAN باز نمی‌کند. تنها راه ورود، `dst-nat` مربوط به LAN در
  `04-admin.rsc` است و تا `XrayAdminPassword` خالی باشد پنل خاموش است.

دو اندازه‌گیری متفاوت، هر دو از خود روتر و هر دو نمونهٔ کوچک روی اینترنت خانگی:

`docs/benchmarks.md`.

## محدودیت‌ها

- شبکه‌ی کانتینر روی این رده سخت‌افزار CPU-bound است؛ انتظار سرعت خط سرور را نداشته باش.
- IPv6 ندارد (دستگاه مرجع IPv6 خاموش دارد).
- xhttp/splithttp پشتیبانی نمی‌شود؛ sing-box چنین ترنسپورتی ندارد و پنل هم صریح
  همین را می‌گوید.
- یک روتر، یک نود فعال. حساب‌داری کاربر و پنل چندمستأجری ندارد.
- root کانتینر با کرنل RouterOS مشترک است. `docs/security.md` را قبل از نصب روی
  دستگاهی که مالکش نیستی بخوان.
